# M5b: the Glue job, three runs (2026-10-10 and 2026-10-11)

The Glue stack (ADR-0023) was applied in the workload account and the job `ecp-glue-shape` was run three times. Everything below was read from the repository, the CI logs and read-only AWS calls; an independent reviewer repeated the checks of run 3. The data is synthetic (the seeded price generator), so nothing here comes from EIA. The bucket is `ecp-glue-<acct>-<region>`.

## The causes and the fixes
- **Run 1, #64.** Glue appends its own arguments to the script's command line (`--JOB_NAME`, `--JOB_ID`, `--JOB_RUN_ID`, the continuous-log flags and internal ones), and the script called `parse_args()`. The local tests had never passed Glue's extra arguments. The job now uses `parse_known_args`, requires its six own arguments with no defaults, and logs the ignored ones by name only. The test builds the command line from the names in run 1's log, with placeholder values. The same PR added the first update mode to the plan check.
- **Run 2, #65.** The error log held a `cloudwatch:PutMetricData` AccessDenied at shutdown, from the metrics sink that `--enable-metrics` starts. The job is a plain SparkSession, not a GlueContext, so the metrics add little: the argument was removed and no permission granted. And `/aws-glue/ecp-shape` stayed empty, because Glue 5 ignores `--enable-continuous-cloudwatch-log`, `--continuous-log-logGroup` and `--enable-continuous-log-filter`; `--custom-logGroup-prefix` writes to `<prefix>/output` and `<prefix>/error`. Terraform now manages those two groups (14 days) and dropped the empty one.
- **Before run 3, #66.** An independent reviewer found that `saveAsTextFile` refuses an existing directory, so a third run into the second run's output would have failed with `FileAlreadyExistsException`, and reproduced it locally. The job now deletes each of its two output paths (never their parent) through the Hadoop FileSystem just before writing; the role already had `s3:DeleteObject` on `m5/*`. The test runs `main` twice to one output.

## How the applies were checked
Each apply used a saved plan whose SHA-256 the owner approved, and a plan check pinned to exactly the expected change set (`scripts/glue_plan_check.py`, written test-first for each step). After each apply a fresh plan JSON had to show 0 changes and 0 drift; the text "No changes" is not evidence. Twice the JSON held drift that the text did not mention, all of it the provider's read-back after create (empty collections for null, `tags` null to `{}`, `version_id` `""` to `"null"`); each time a refresh-only plan was reviewed and applied before the next strict update plan. Applies: the 13 creates; the arguments and script update; the Glue 5 logging change (2 creates, 1 update, 1 delete); the script update for the rerun fix; and two refresh-only applies that changed no resource.

## Actual cost
Glue 5.1 costs $0.44 per DPU-hour (ca-central-1, AWS Pricing API, 2026-10-10). The three runs used 59, 120 and 129 DPU-seconds: 308 together, 0.0856 DPU-hours, **about $0.04**. The stack's other resources (an S3 bucket holding a few kilobytes, two managed log groups of a few kilobytes) cost cents or less. The figure is computed from the run records (`get-job-run`), not read from Cost Explorer. The M5 estimate for Glue was $0.07 to $0.15 a run.

## Known limitation: an interrupted rerun can delete the last good output
The job deletes its two output paths and then writes them, and it replaces `shape_params.csv` and `shape_params.sha256` separately. A rerun that fails after the delete (or between the two writes) leaves no output, or a CSV without its matching hash, and the last good output is gone. Nothing reads these files yet. **It must be fixed before M5c reads them:** each run writes under a run-scoped prefix, a small completion record is written last, and the Redshift load reads only completed runs and checks the hash before loading.


**Update:** the run-scoped output and completion record that remove this limitation are in ADR-0023, "Each run writes its own prefix (M5c-0)".

## Not shown

Redshift (M5c) is not built.
