## The budget filter change
- **In place:** the $40 budget's legacy `cost_filter` went from `TagKeyValue` `user:project$energy-curve-platform` to `LinkedAccount` = `ecp-workloads`, referenced from `aws_organizations_account.workloads.id`. Nothing else on the budget changed: the cost types, limit and notifications stayed as they were.
- **Why not the OR** of the account and the tag: the switch to `filter_expression` would have sent both filter styles, which the Budgets API refuses. ADR-0021, Q2, records the decision.
- **The tag-key form** for a `FilterExpression` (`user:project` or `project`) was never confirmed by a primary source, and is unused.
- **Consequence:** tagged costs left in the management account are no longer counted by the $40 budget. That means the state bucket today, cents a month. The account-wide $20 budget still covers them, and the `project` cost allocation tag stays `Active`.

## Accepted drift
- **What:** the post-apply re-plan reports `aws_ssoadmin_permission_set.readonly` with `tags` read back as `{}` where state had null. It is planned `no-op`.
- **Why it's harmless:** it's the provider's tags normalization, seen earlier on the account, OU and SCPs, here on the permission set this apply created. It changes nothing in AWS.
- **Decision:** the user accepted it on 2026-10-06 and chose not to run a refresh-only apply for it now.
- **Effect on later plans:** it stays in later `infra/org` plans' `resource_drift` until a state write records it. A later plan check must expect it, or a refresh-only apply must clear it first.
